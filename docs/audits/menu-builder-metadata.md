# M2 menu product metadata

Updated 12 October 2026. Metadata behavior is implemented in the real Menu Builder source. The additive database migration and shared-environment/hosted acceptance remain outstanding; see [decision 0009](../architecture/decisions/0009-menu-product-metadata.md), the [API contract](../api/api-contracts.md) and [database schema](../database/database-schema.md).

## Menu editor behavior

- Product forms expose an optional SKU/reference, **Contains** and **May contain** allergen declarations, dietary declarations, preparation guidance minutes and localized preparation notes. The SKU is an ordinary editable text input that fills the metadata column; its label no longer caps the width. API validation and normalization remain authoritative.
- Each allergen declaration is a localized click-to-toggle popover with 14 controlled EU allergen checkboxes, a selected count and a clear action. Selected values submit under the existing field names. Dietary declarations remain separate checkboxes. The dedicated Allergens tab has been removed from the menu workspace.
- The product list and editor retain readable titles and descriptions at narrow widths. The shared Lovable workspace and menu scope now use `overflow-wrap: break-word` instead of `anywhere`; the product text flex child grows within its column. Previously, `anywhere` reduced its min-content width to zero while the child had `min-width: 0` and no flex growth, so squeezed layouts could render text one character per line.
- The unselected-product prompt no longer reserves `60vh`. At desktop widths, the menu layout grows to short content and caps at the available menu viewport when lists are long; the product list then scrolls independently, while **New category** and **Manage categories** stay together at the bottom of the category column. At narrower viewport widths, both actions stay in one fixed bottom row. The menu workspace no longer creates a container-query containing block for those viewport-fixed actions.
- Base UI renders each checkbox’s form input as an absolutely positioned, visually hidden sibling of its button. The shared Checkbox now wraps both in a positioned inline container, keeping those inputs with their control instead of extending the page scroll range when a long product editor is scrolled. Desktop menu clipping uses `overflow: clip`, which clips without adding another scroll container.
- On narrow screens, the selected product panel follows the document scroll rather than trapping the page in a nested scroll region. Product editing keeps **Cancel** and **Save** fixed directly above the category action row. Preparation guidance and note inputs share the same label height so their controls align on desktop.
- Product photography uses the available editor width: the preview/gallery sit to the left, and framing, image details, guidance and photo actions sit to the right on desktop. The two areas stack on narrow screens.
- The category archive confirmation uses explicit responsive viewport sizing in the shared alert dialog. Keep spaces encoded in Tailwind `calc()` utilities so the popup does not collapse to its intrinsic content width.
- Discount form labels use a shared fixed label row so helper text under **Discount code** cannot push its input out of alignment with **Name**. On phones the workspace app bar keeps its 44px touch targets while reducing vertical padding and showing icon navigation with visually hidden accessible labels. Multi-select popovers carry the active workspace visual scope across their portal so their selected colors match the rest of the menu.
